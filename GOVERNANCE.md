# Governance

pkx is currently maintained by [AmpedWasTaken](https://github.com/AmpedWasTaken). Everyone may propose or review changes and contribute under the [MIT license](LICENSE); contributing does not automatically grant repository permissions.

Small bug fixes can be reviewed directly. Significant CLI changes, new package managers, bundle schema changes and security-sensitive behavior should have an issue discussing compatibility and trade-offs first. Where possible, keep reasoning and decisions linked to the issue or PR.

Maintainers make final merge/release decisions. Green CI is necessary but not sufficient for approval or production readiness. Maintainers may request changes based on security, compatibility, complexity or maintenance costs. No guaranteed review or release schedule exists.

Sustained, constructive contributions—including reviewing others' changes—may lead to discussing additional maintainers. Repository access must be explicitly granted by an existing maintainer; there is no automatic promotion.

Release tags build archives and checksums. Stable release announcements should follow cross-platform verification. Security reporting follows [SECURITY.md](SECURITY.md).
